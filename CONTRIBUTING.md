# Contributing to Seyk

Thanks for helping. Seyk finds where information is in local content and returns
verifiable evidence without sending that content anywhere. Read
[docs/NORTH_STAR.md](docs/NORTH_STAR.md) before proposing a feature; it lists
what Seyk will and will not do.

## Before you start

- **Open an issue first** for anything larger than a small fix, so the approach
  can be agreed before you write code.
- **Security problems** go through [SECURITY.md](SECURITY.md), not public issues.

## Build and test

The toolchain is pinned in `rust-toolchain.toml` (Rust 1.99.0); the minimum
supported Rust version is 1.89.

```bash
cargo fmt --all --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
cargo test -p seyk-core --no-default-features --locked
cargo test -p seyk-core --features pdf,pdf-render --locked
cargo deny check licenses
python3 scripts/check_embedding_dependencies.py
```

Model-backed tests are `#[ignore]`d and need locally provisioned weights
(`seyk model download`). Tests never download models.

## Rules for changes

- **Ranking or segmentation changes need a benchmark run.** Run the public
  retrieval harness in [docs/benchmarks.md](docs/benchmarks.md) and include the
  SciFact and NFCorpus nDCG@10 before and after in the pull request.
- **No private or copyrighted content in the repository.** Test fixtures must be
  generated by code in the repository or carry a public-domain/CC0 or compatible
  licence. Never commit recordings from macOS `say` or other system voices;
  generate them at test time into an ignored directory.
- **Keep the privacy guarantees.** Content, queries and vectors are never sent
  to a third-party service, and the cache never stores source text in readable
  order.
- **Dependencies** must pass `cargo deny check licenses`; new third-party assets
  need an entry in [THIRD_PARTY.md](THIRD_PARTY.md).

## Pull requests

Keep each pull request focused. Describe what changed, why, and the exact
commands you ran with their results. By submitting a contribution you agree that
it is licensed under the [Apache License 2.0](LICENSE).

If your change is visible to users, add one line under `## [Unreleased]` in
[CHANGELOG.md](CHANGELOG.md), in the matching section (Added, Changed,
Deprecated, Removed, Fixed or Security). Mark breaking changes with
**Breaking:**.
