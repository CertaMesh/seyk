# 4b compatibility spike report

Recommendation: **revise 4b**. Retain Hayro as the scan-retrieval candidate; defer OCR pending a compatible upstream adapter and complete model conversion provenance. Do not implement or ship the approved 4b design unchanged. No MSRV raise, fork, runtime replacement, second backend, or product-crate change was made.

Scope: throwaway `spike-4b` from main `f9af387`, isolated Cargo workspace. [Draft PR #15](https://github.com/CertaMesh/seyk/pull/15) exists only for native CI and will be closed after this report. Code commit `b12256c` is SSH-signed. Later commits only preserve notices, reports and measurements. Sources and raw measurements are under `tools/spike-4b/evidence/` on that branch.

Judgment calls and boundaries:
- G2 failure does not prevent renderer, geometry, asset-load or scan-retrieval measurements. The load-only probe uses the already-approved ORT; it is not a substitute OCR pipeline. No corpus OCR ran.
- The Design's PDFium alternative is unnecessary because Hayro passes. No eligible OCR alternative remains in the Design: current oar-ocr0.10.0 (also0.9.x) declares Rust1.95; ocrs switches to RTen and Tesseract adds a different native inference stack. No alternate runtime/fork was tried.
- Full OCR cargo-deny fails the existing policy for BSD-2-Clause (av1-grain/rav1e/v_frame) and NCSA (libfuzzer-sys), pulled through paddle's unconditional image defaults. These are policy additions, not a finding of copyleft. No global allow or package exception was added. A separate native-source audit also found Clipper6.4.2's BSL-1.0 notice inside the MIT-labelled clipper-sys package; notice copied and hashes recorded. Cargo metadata passing for geometry is not a complete native licence approval.
- Minimal ORT baseline versus ORT+renderer+native geometry measures incremental spike binary size; it is not the product CLI delta. Model weights are excluded. Models/generated synthetic PDFs/PNGs remain ignored, never committed. Product crates, root lockfile/config, README banner and private vault content were untouched.

Quality and performance:
- Corpus: authored synthetic English text,20 letter-sized image-only PDFs, one page each. Hayro first rasterizes text using bundled fonts at long edge2200; a new PDF embeds only that image; retrieval re-renders the full page at2048. Titles20pt, body13pt, clean single-column pages. Ten semantic queries, two identifiers, two exact-title queries, ten additional distractor pages. Queries/ground truth were fixed before the first embedding run. Pure cosine ranking, no filename/lexical boosts and no OCR. `corpus.json` is Apache-2.0.
- Gemma revision `daa72c51243991dfcaf9f9137d2c573d8f7790c0`, default dimension256, Q8, default ORT thread policy, image SearchDocument/query SearchQuery. Load523.6ms. Apple M5 Max,64GiB, macOS26.5. Independent processes with network denied. First measured image-embedding p50/p95=2354.6/3136.9ms (20pages); query p50/p95=68.7/83.0ms (14queries); process maxRSS1,401,339,904B including model/load/query work.
- Isolated scan rendering p50/p95=33.93/34.55ms (20pages), maxRSS369,147,904B. PNG encoding included adds roughly3ms/page (render+encode p50/p95=37.10/37.64ms). Generation and repeated determinism checks are excluded from isolated render numbers.
- Separate50ms external RSS sampling: render p50/p95=221,937,664/356,843,520B (24samples); embed p50/p95=1,360,330,752/1,361,444,864B (693samples). Sampling spans startup/model load and page/query work. These percentiles are not per-page peaks. Sampled maxima are not kernel high-water marks. The repeat retained100% Recall@5/MRR1.0; embedding p50/p95 varied to1906.9/2466.9ms. Shared-host measurements, no latency gate or tuned thresholds.
- Limit: this proves the declared clean synthetic minimum only; dense/small/damaged scans, multi-column ordering, accented OCR, unsupported-language behavior and real-corpus recall are not established. OCR extraction accuracy, missing/dictionary-mismatch inference behavior and stale OCR evidence need a future compatible adapter. No private evaluation was used.

Reproduction: from tools/spike-4b, put the selected Rust sysroot/bin first in PATH (ensures actual rustc version), then `cargo build --release --locked --features render,native-ocr` with Rust1.89/1.99; `cargo check --locked --features ocr` reproduces8 failures; `cargo tree --locked --features ocr -i ort` shows one version. `cargo deny --locked --features render,native-ocr,embed check --config ../../deny.toml licenses` passes Cargo metadata; all-features version fails. Build with `--features render,native-ocr,embed`, run `render`, then `embed` against explicitly provisioned pinned Gemma. `sandbox-exec` deny network and font directories; `/usr/bin/time -l` for peak RSS; `profile.py` for sampled RSS. No local services or dependency fork; all spawned Solo terminals closed.

Link-detail correction: Windows adds only `bcryptprimitives.dll` beyond the baseline imports, a [Windows system RNG DLL](https://learn.microsoft.com/en-us/windows/win32/seccng/processprng). Existing ORT imports of DirectML/D3D and MSVC runtime remain; this is not a claim of a CRT-free Windows executable or GPU renderer. macOS and Linux add no dynamic-library imports.
